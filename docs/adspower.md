# AdsPower 自管 SOCKS5，电脑仅提供中转

[返回 README](../README.md)

## 两种接法不要混用

| 接法 | AdsPower 填写 | 谁连接最终 SOCKS5 |
| --- | --- | --- |
| 使用本机代理 | 本机 HTTP 地址和实际端口 | Clash / Mihomo |
| 自管 SOCKS5（本文） | 远端 SOCKS5 地址、端口、合法凭据 | AdsPower；电脑仅中转到该服务器 |

```text
AdsPower（自己完成 SOCKS5 认证）
  → 本机 TUN（匹配服务器 IP + TCP 端口）
  → RELAY_NODE → 固定 SOCKS5 服务器 → 网站
```

这不是让网站从中转直接出站，最终网站仍看到 SOCKS5 出口。AnyTLS 等中转协议的端口，也不能直接作为 AdsPower 的 SOCKS5 端口填写。

## 为什么会连接失败

整机默认已经使用“中转 → SOCKS5”时，应用又连接同一个 SOCKS5，服务器连接本身可能再次被送进 SOCKS5，形成重复路径。

`ERR_SOCKS_CONNECTION_FAILED` 仅是错误类别；认证、端口、白名单、过期和不可达也可造成类似现象，不能只凭截图判定根因。

## 精确服务器传输例外

以下是不可连接的公开示例，只在私有副本替换真实端点：

```yaml
# 公网 UDP/IPv6 拒绝规则之后，最终 MATCH 之前。
- AND,((NETWORK,TCP),(IP-CIDR,203.0.113.10/32),(DST-PORT,1080)),RELAY_NODE
- MATCH,Fixed-Egress
```

不只匹配 IP 而放开所有端口，也不把 AdsPower 整个进程无条件改成中转直出。本规则按地址和端口匹配，其他应用使用同一 SOCKS5 端点时也生效；不是进程隔离。

使用仓库脚本时，在私有副本设置 `appManagedSocks: true`。仅临时修改生成配置，可能在 GUI/订阅重生成时丢失。本例针对固定 IPv4 端点，域名、多地址或 IPv6 端点需要另行设计。

## AdsPower 内如何设置

保留 SOCKS5 类型、远端地址/端口和合法凭据，不改成本机 HTTP。核对供应商并发和认证限制，凭据不发聊天或公开仓库。

电脑要让这条连接进入 TUN，系统保护允许内核连接中转；不需要放开公网 UDP/IPv6，更不应放开整个 AdsPower 物理直出。

## 脱敏案例：2026-10 的一次修复

- 修改前，应用自管 SOCKS5 的匿名请求失败，curl 退出码 97。
- 加入精确例外后，同类请求连续两次成功，均为预期出口，单次约 2 秒。
- 运行态显示 AND 规则命中，服务器传输只经中转。
- 原本机 HTTP 入口仍回显相同出口，其他规则未变。
- 内核语法检查、热加载、脚本模拟重生成通过。

原始 IP、节点名、设备路径和截图不公开。以上是网络探针结果，不是 AdsPower 所有环境的通用认证：当时本地 API 不可读取，未通过它核验具体环境字段。浏览器页面、账号和长期稳定性分别验收；约 2 秒是请求耗时，不是 ping。

## 回滚与迁移

先备份持久脚本和生成配置；回滚只撤回本次例外，保留其他编辑，语法检查后重载并验证原入口。旧故障可能重新出现。

Windows 可采用相同规则意图，但 TUN 与系统保护必须现场适配；Mac 测试不代替 Windows 验收。
