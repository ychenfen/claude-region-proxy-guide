## 按层验收，不用一个 IP 分数代替测试

| 层级 | 检查 | 通过证据 |
| --- | --- | --- |
| 本机入口 | 实际端口、进程、监听范围 | 应用确实连接正确入口，未对外暴露 |
| 代理传输 | 中转到 SOCKS5 的路径、认证、白名单 | 实际连接和规则命中，不只是 GUI 选中 |
| 公网 TCP | 显式本机代理与无代理环境变量的 TUN 请求 | 连续回显预期出口；TLS 校验正常 |
| 国内站点 | 当前规则是否仍有 DIRECT 绕行 | 内核连接记录符合选定策略 |
| DNS | 业务 DoH 与中转引导 DNS | 业务走固定组，引导例外可解释 |
| UDP/STUN | 多个 IPv4 目标和可用 IPv6 目标 | 结合拒绝规则/计数、目标可达对照；不只看 timeout |
| WebRTC | 实际使用的浏览器 | 检查公网 srflx/relay 候选与预期是否一致；host/mDNS 单独解释 |
| IPv6 TCP | 字面 IPv6、显式代理和无代理路径 | 无绕过；不能只看 AAAA 开关 |
| TUN 停止 | 独立恢复保险就绪后临时关闭 | 原生直连失败，但显式代理正向对照仍成功 |
| 内核退出 | 本机可恢复时停止代理 | 公网不回退直连，恢复后仍为预期出口 |
| 持久性 | 配置重生成、重启、唤醒、切网 | 各场景逐项测试，不用模拟代替实测 |
| 实际业务 | 长连接、晚高峰、合法账号会话 | 单独记录失败率和恢复，不从匿名探针推断 |

`curl --noproxy '*'` 可以绕过 curl 的显式代理选择，但**不会绕过操作系统 TUN**。只有在受控关闭接管、选定真实公网目标后，才适合作为物理直连的负向测试。

不使用无效测试地址来“证明阻断”。没有原生 IPv6 能力时，IPv6 失败本身也不能证明防火墙生效。不要关闭证书校验掩盖 TLS 问题。

## 脱敏案例的证据范围

2026-10 的 Mac 样本完成过：本机 HTTP/TUN 出口对照、业务 DoH 路由检查、UDP/STUN 拒绝证据、浏览器 WebRTC 检查，以及临时关闭 TUN 后的直连失败/显式代理成功对照。AdsPower 自管 SOCKS5 的后续修复见 [独立案例](adspower.md)。

以上不包含真实 Windows 部署，也不等于重启、唤醒、切网、彻底退出客户端、长期稳定性和账号会话全部通过。仓库不公开原始日志、用户环境配置或设备路径，案例用于解释排查方法，不是第三方可直接复核的完整原始数据集。

## 诊断顺序

1. 区分本机到中转、中转到出口、出口到目标三段，确定失败发生在哪层。
2. 检查端口/认证和实际运行态，避免仅靠反复刷新。
3. 保持同一出口，对比中转线路；改变多个变量后无法判断是谁带来改善。
4. 保留正向联网对照；timeout、DNS 失败和认证失败分别记录。
5. 只改最小范围，先备份，语法通过后加载，失败立即恢复。

## 脱敏规则

| 原始内容 | 公开写法 |
| --- | --- |
| 真实代理 IP / 端口 | 文档地址 `203.0.113.10` / 示例端口 `1080` |
| 服务商中转域名 | `relay.example.invalid` |
| 用户节点名 | `RELAY_NODE`、`US_EXIT` |
| 用户名、密码、订阅、token、Cookie | 不复制，描述“本机安全提供” |
| 个人绝对路径、用户/设备/环境标识 | 相对路径或角色描述 |
| 完整配置、截图、网络日志、备份 ZIP | 不公开；只摘取必要且脱敏的结论 |

回环、RFC 文档地址、明确的私有网段以及示例中的公共 DNS 地址不是个人出口。例子必须写明不能直接使用；不能用另一个人的真实 IP 替换自己的。

分享前运行 `node tests/verify.cjs`，还要人工检查新增文件。正则扫描不能证明“没有任何秘密”；截图与二进制尤其不能仅靠文本搜索。

本次旧截图从待提交树移除，本机仍可恢复；不把私有备份再加入仓库。`.gitignore` 不能让已跟踪文件自动脱敏，也不能删除历史。
